# QuickDiskRescue ヘルプ

Windows がマウントできないディスクから、フォルダ構造を保ってファイルを別ドライブへ救出するツールです。管理者権限で起動します。

CrystalDiskInfo のクローンではありません。SMART の見え方を近い形にしているだけです。EaseUS の全機能互換でもありません。

## 起動

1. `QuickDiskRescue.exe` を起動する。UAC が出る。管理者で動かす。
2. 右上のバッジは常に「ソース読取専用」。GPT修復以外はソースへ書かない。
3. 起動直後、左に物理ディスクが一覧される。診断はまだ走らない。ディスクをクリックすると診断が始まる。
4. 右上の「🌐 English」で英語ヘルプに切り替わる。言語はヘルプ本文にも効く。
5. WebView2 Runtime が無いと起動できない。メッセージが出たら Runtime を入れる。

対象ディスクは、可能なら別 PC に付けて読む。今動いている Windows の C: で試すと、BitLocker やロックで中身が出ないことが多い。

## 画面の見方

### 左（ディスク一覧）

`Drive0  (C:)  476.9 GB  SAMSUNG...` のように出る。

- `DriveN` は `\\.\PhysicalDriveN`。N は Windows のディスク番号。
- 括弧内は、その物理ディスクに付いているドライブレター。無いディスクは括弧なし。
- サイズはディスク全体。区画のサイズではない。
- クリックすると診断が走り、経過が動き出す。

イメージを開いたあとも、左の一覧は物理ディスクのまま。開いたパスはステータスと診断結果で確認する。

経過は、診断・消失走査・イメージ・救出・カービング・GPT修復・ツリー読込が走っているあいだだけ動く。完了または失敗で止まる。止まっている数字は最後の作業の所要時間。

### 上のボタン

診断 / 消失走査 / イメージ保存 / フォルダ救出 / カービング / GPT修復 / 停止

先に左でディスクを選ぶ。未選択のまま GPT修復を押すと、ステータスに `select a disk first` と出る。

### 中央（上から）

1. ハードウェア（容量、セクタ、バス、型番、GPT 要約）
2. SMART（健康バッジ、温度、属性表）
3. 区画一覧（1行が1区画。クリックでその区画のツリーを読む）
4. フォルダツリー（名前 / サイズ / 状態）

### 下のステータス

完了、失敗、BitLocker の説明、進捗（`image 123 MB / 1.0 TB`）が出る。作業の成否はここを見る。

### メニュー

- ファイル → イメージを開く（Ctrl+O）。生ディスクのコピー（.img など）を診断対象にする。
- ファイル → 終了（Ctrl+Q）
- ヘルプ → ヘルプ（この文）
- ヘルプ → バージョン情報

## 原則

1. 壊れたディスクへ書くのは GPT修復だけ。それ以外は読取専用。
2. 実ディスクを何度も舐める前に、別ドライブへイメージ保存する。SMART が注意・異常なら、走査や修復より先にイメージ。
3. 救出ファイルの保存先は、壊れたディスク自身にしない。この版は同じディスクへの保存を自動では拒まない。自分で別ドライブを選ぶ。
4. 区画の種類を見てからツリーを信じる。Recovery や EFI は C: ではない。
5. BitLocker は鍵なしではフォルダ救出できない。カービングでも復号しない。

## 基本の順番

1. 左で対象ディスクを選ぶ。またはファイル → イメージを開く。
2. 診断が自動で走る。ハードウェア、SMART、区画、GPT を読む。
3. SMART と GPT を見て、下の「状態と処置」に当てはめる。
4. 別ドライブへイメージ保存する（推奨。SMART が注意・異常ならほぼ必須）。
5. 以降の消失走査・GPT修復・フォルダ救出は、可能ならイメージを開いて行う。
6. 区画一覧で NTFS（Recovery 以外）をクリックし、ツリーが出るまで待つ。
7. ツリーで元フォルダを選んでから「フォルダ救出」。Windows のフォルダ画面は保存先。

## 状態と処置

迷ったらこの表だけ見る。

| 状態 | 画面の目安 | 処置 |
|---|---|---|
| ディスクは見えるがエクスプローラーに出ない | 左に DriveN、区画はあるがレターなし | イメージ保存 → NTFS（Recovery 以外）をクリック → フォルダ救出 |
| 容量が実物と違う | mismatch:true。size と geom が違う、または LastUsable が実 LBA と違う | イメージ保存 → GPT修復（確認が複数）→ ディスクを選び直して再診断 |
| GPT の片方だけ壊れている | primary か backup の crc が 0 | イメージ保存 → GPT修復 |
| 両方の GPT が壊れている | GPT修復が `no_valid_gpt_header` | GPT修復はしない。消失走査で NTFS の位置を確認 → 表に NTFS があればそれを選んでフォルダ救出。なければカービング |
| 表に無い NTFS が残っている | 消失走査のあと `lost: N` が増える | 消失走査は位置の確認だけ。救出は区画一覧の NTFS 行をクリックしてフォルダ救出。候補オフセットからの直接救出はこの版に無い |
| ツリーに Users / Windows が出る | 区画が NTFS で Recovery ではない | ツリーでフォルダを選ぶ → フォルダ救出。保存先は別ドライブ |
| ツリーが空、`ntfs_not_found` | EFI / MSR / FAT、または壊れたブート | NTFS ではない行を選んでいる。Basic + NTFS の行を選ぶ |
| Recovery のフォルダだけ出る | 区画名が Recovery、容量が小さい（数 GB） | OS の C: ではない。C が BitLocker ならその行を見よ |
| BitLocker | 区画が BitLocker | 解除済みならそのままフォルダ救出。ロックなら 48桁 / パスフレーズ / .bek。鍵が無いなら不可 |
| SMART が注意・異常 | 健康が注意または異常。pending / 代替セクタが 0 より大きい | 実ディスクへの消失走査や修復を急がない。先にイメージ。以降はイメージを開いて作業 |
| SMART が取れない | `SMART n/a (... )` | 診断と救出は続行してよい。健康判定は使わない |
| ファイル名は捨てて中身だけ欲しい | MFT が読めない、ツリーが空、区画表も死んでいる | カービング。名前は連番。保存先は別ドライブ |
| 今動いている Windows の C: で試している | 左に (C:) | C が BitLocker ならフォルダ救出はできない。テストするなら暗号化されていない NTFS か、保存したイメージ |

### ディスクは見えるがエクスプローラーに出ない

Windows がマウントしていないだけ、ということがある。このアプリはドライブレター無しで生読みする。区画表が生きていて NTFS ブートが読めれば、エクスプローラーに出なくてもツリーは出せる。

先にイメージを取り、NTFS（Recovery 以外）をクリックする。ツリーに目的のフォルダがあればフォルダ救出。

### 容量が実物と違う

不完全なシャットダウンや書き込みの途中切断のあと、GPT の末尾（LastUsable / AlternateLBA）が実ディスクサイズと食い違うことがある。画面では `mismatch:true`。

GPT修復はヘッダとパーティション配列と Protective MBR だけを、実サイズに合わせて書き直す。ファイルの中身は変えない。必ず先にイメージ。実ディスクでは確認ダイアログが複数出る。

### 両方の GPT が壊れている

修復は「CRC が通る側」を正としてコピーする。両方無効なら書く根拠が無いので `no_valid_gpt_header` で拒否する。このとき GPT修復を繰り返しても直らない。消失走査かカービングへ進む。

### BitLocker

区画の先頭マジックが `-FVE-FS-` だと `BitLocker` と出す。

Windows がすでに解除しているボリューム（今動いている PC の C: など）は、鍵なしでフォルダ救出できる。ロックされているときは回復パスワード（48桁）、パスフレーズ、または `.bek` を入力する。鍵はメモリだけ使い、保存しない。解除は Windows（WMI / manage-bde）に任せる。イメージが `.vhd` / `.vhdx` ならアタッチしてから同じ。

鍵が無い、または他マシンの TPM だけのときは出せない。

## 区画の種類

クリックした行だけを読む。種類が違うとツリーの中身も変わる。行の形は次のとおり。

`#2 Basic NTFS 100.00GB`

| 欄 | 意味 |
|---|---|
| #N | 区画インデックス。ツリー読込と CLI の `--partition` に使う |
| 役割 | EFI / MSR / Basic / Recovery など |
| ファイルシステム | NTFS / BitLocker / FAT32 / exFAT / GPT / 空 |
| GB | `(最終LBA - 先頭LBA + 1) × 512` を GB にした値。4K セクタでも表示は 512 換算 |
| 名前 | GPT の区画名。空のこともある |

| 表示 | 意味 | フォルダ救出 |
|---|---|---|
| EFI | 起動用 FAT | 不可（`ntfs_not_found`） |
| MSR | Windows の予約 | 不可 |
| Basic + NTFS | 通常のデータ / OS | 対象 |
| Basic + BitLocker | 暗号化された NTFS | 不可（鍵なし） |
| Recovery + NTFS | 回復区画。小さいことが多い | 回復用ファイルだけ。C: の代わりではない |
| FAT / exFAT | メモリカードや ESP など | この版のフォルダ救出は NTFS のみ |

## 自動で選ばれる区画

ディスクをクリックした直後、次の順で 1 行が自動選択される。

1. Recovery ではない NTFS のうち、いちばん大きいもの
2. それが無く BitLocker がある → ツリーは読まない。BitLocker の説明を出す
3. それも無い → Recovery の NTFS のうちいちばん大きいもの

BitLocker の行をクリックしてもツリーは出ない。データ NTFS を自分でクリックすれば、その区画のツリーになる。

## ハードウェア行の読み方

上の灰色エリアに 4 行出る。

| 表示 | 意味 |
|---|---|
| `C:  size: 476.9 GB  geom: 476.9 GB` | size は実ハンドルの容量。geom は IOCTL のジオメトリ。イメージではレターは空 |
| `sector: 512 / phys 4096  bus: NVMe` | 論理セクタ / 物理セクタ / バス |
| `model: ...` | 型番。イメージでは空やファイル名相当 |
| `GPT primary:true crc:1 backup:true mismatch:false` | 先頭 GPT の有無、先頭 CRC、末尾 GPT、容量の食い違い |

`crc:1` は検査合計が通った。`crc:0` はその側が壊れているか、読めていない。

`mismatch:true` の条件は次のいずれか。

- `gpt_last_usable_lba + 34` が `disk_lbas` と一致しない（かつ +1 でもない）
- `geom` と `size` が食い違う

## SMART（CrystalDiskInfo 風の表示）

ディスク単位。区画ではない。BitLocker でもディスクの健康は読めることがある。自己診断テスト（短時間・長時間）は実行しない。死にかけディスクを負荷で壊さないため。

| 表示 | 意味 |
|---|---|
| 正常 | 閾値割れなし。代替・pending・回復不能が 0 |
| 注意 | 代替処理済 / pending / 回復不能が 0 より大きい、または温度が高い |
| 異常 | 属性が閾値以下、または OS の予測失敗（IOCTL_STORAGE_PREDICT_FAILURE） |
| 温度 | センサ値。取れないこともある |
| POH | 通電時間（時間） |
| Count | 電源投入回数 |
| SN / FW | シリアルとファームウェア |
| spare / used | NVMe の残り予備と使用率 |
| SSD / N RPM | IDENTIFY の回転数。0 または 1 なら SSD 扱い |
| 属性表 | ID（16進）、名前、現在、最悪、閾値、RAW |

よく見る属性:

| ID | 名前 | 見方 |
|---|---|---|
| 05 | 代替処理済セクタ数 | RAW が 0 より大きいと注意。増えていたらイメージを急ぐ |
| 09 | 使用時間 | 通電時間 |
| C5 / 197 | 代替処理待セクタ数 | 未処理の不良。0 より大きければ注意 |
| C6 / 198 | 回復不可能セクタ数 | 読めないセクタ |
| C2 / 194 | 温度 | 高いと注意 |

USB ブリッジは SMART を通さないことがある（`SMART n/a`）。健康判定は使わず、救出は続行してよい。

行が赤や黄なら、その属性が注意または異常。実ディスクへの全セクタ走査はそのあと回し。

## GPT の見方

診断 JSON とハードウェア行の対応。

| 表示 | 意味 |
|---|---|
| gpt_primary / backup | 先頭と末尾に GPT ヘッダがあるか |
| crc | 検査合計。0 ならその側は壊れている |
| gpt_last_usable_lba | GPT が「使える最後の LBA」と思っている値 |
| disk_lbas | 実ディスクのセクタ数（size / sector） |
| size_mismatch | 上の食い違い。表示容量が実物と合わない |

GPT修復が直すもの: Protective MBR、primary ヘッダ、パーティション配列、backup ヘッダと配列の位置。CRC が通る側を正とする。ファイルデータは触らない。

## ボタンの詳細

### 診断

先頭と末尾の GPT、各区画の種類、SMART を読む。ディスクをクリックしたときも走る。ソースへは書かない。

終わるとステータスは `diagnose done`。続けて自動でツリーを読む（BitLocker だけのときは読まない）。

### 消失走査

ディスク全体をセクタ単位で読み、次のシグネチャを探す。ファイルコピーはしない。

| シグネチャ | 意味 |
|---|---|
| `EFI PART` | GPT ヘッダ |
| `NTFS    ` | NTFS ブートセクタ |
| `FILE` | MFT レコード |

区画一覧の下に `lost: N` と出る。大容量だと時間がかかる。生きている NTFS では `FILE` が大量にヒットする。本命は、表に無い位置の `NTFS`。

この版は、ヒットしたオフセットからフォルダ救出を始めない。位置の確認用。救出は区画一覧の NTFS 行から行う。

### イメージ保存

選んだディスクの生バイトを、指定ファイルへ複製する。押すと Windows のファイル保存ダイアログが出る。保存先はファイル名（フォルダではない）。

- 読めない箇所はゼロ埋めし、`保存名.img.badlba.txt` に LBA を残す。
- ソースへは書かない。
- 保存先の空きは、ディスク容量と同じだけ必要。
- 進捗はステータスに `image 済み / 全体`。
- 完了は `image {"ok":true,"path":"...","bad_lbas":N}`。

イメージを取ったあと、ファイル → イメージを開くと、以降の診断・救出・GPT修復をファイルに対して行える。死にかけディスクへの再走査を減らせる。

イメージに対する GPT修復は、実ディスクより安全。まずイメージで試し、結果を見てから実ディスクに適用する。

### フォルダ救出

Windows のフォルダ画面は保存先である。壊れたディスク上のフォルダを選ぶ画面ではない。元フォルダは、先に画面内のツリーで選ぶ。

1. 区画一覧で NTFS を選ぶ（Recovery 以外。ツリーが出るまで待つ。大きいボリュームは時間がかかる）。
2. ツリーで救出したいフォルダをクリックする。選ばなければ全体（`/`）。
3. 「フォルダ救出」を押す。
4. 生きているドライブ上の空フォルダを選ぶ。壊れたディスク自身は選ばない。
5. 完了は `copied N failed M`。失敗件数は圧縮・暗号化 NTFS 属性、読取失敗など。

ツリーの列:

| 列 | 意味 |
|---|---|
| 名前 | フォルダは 📁、ファイルは 📄 |
| サイズ | ファイルサイズ。フォルダは 0 に近いことがある |
| 状態 | `dir` / `file`。削除済みは `DEL`。未使用レコードは `unused` |

`tree failed: ntfs_not_found` はその区画が NTFS として読めない。別の行をクリックする。

### カービング

MFT を使わず、データの先頭バイトでファイルを切り出す。保存先に `carved\jpeg\00001.jpeg` のように連番で出る。元のフォルダ名は付かない。誤検出がある。docx などは ZIP として出ることがある。対応形式は JPEG / PNG / GIF / PDF / ZIP。

Windows のフォルダ画面は、ここでも保存先。完了は `carved N`。

名前が必要ならフォルダ救出を先に試す。カービングは最終手段。

### GPT修復

GPT のヘッダ、パーティション配列、Protective MBR だけを、実ディスクサイズに合わせて書き直す。ファイルの中身は変更しない。

使うとき:

- 実容量と GPT の末尾（LastUsable）が食い違う（`mismatch:true`）
- primary か backup の片方だけ壊れている（crc が片側 0）

使わないとき:

- 両方の GPT が無効（`no_valid_gpt_header`）
- BitLocker のシステムディスクを試し撃ちしたいだけ
- まだイメージを取っていない実ディスク（推奨しない）
- SMART が異常で、まずイメージも取っていない

実ディスクでの確認は 3 段。

1. アプリ内の確認「GPTヘッダだけを書き込みます…」
2. 警告「GPT ヘッダとパーティション表だけをディスクへ書き込みます…」
3. 最終確認「最終確認: 実ディスクの GPT を修復します。よろしいですか？」

イメージファイルでは 1 だけ（MessageBox は出ない）。

結果:

| ステータス | 意味 |
|---|---|
| `GPT repaired (last usable A -> B)` | 書いた。A が旧 LastUsable、B が実サイズに合わせた値 |
| `GPT repair: already consistent` | 直す必要が無かった |
| `GPT repair failed: no_valid_gpt_header` | 両方無効。書かない |
| `GPT repair failed: write_open_failed` | 書き込みハンドルを開けない。他アプリがロック、権限、読み取り専用 |
| `GPT repair failed: write_failed` | 途中まで書いた可能性。イメージからやり直す |

修復後はディスクを選び直して再診断する。`mismatch:false` と crc の復旧を確認してからフォルダ救出へ進む。

### 停止

実行中のイメージ・走査・救出を打ち切る。途中までの救出ファイルは残る。GPT修復の書き込み中は、途中停止より完了を待つ。

## ステータスに出る文言

| 文言 | 意味 |
|---|---|
| 準備完了 | 起動直後。まだディスクを選んでいない |
| diagnose done | 診断完了。続けてツリーを読むことがある |
| tree done (partition N) | 区画 N のツリーを読んだ |
| tree failed: ntfs_not_found | その区画は NTFS として読めない |
| tree failed: open_failed | ソースを開けない |
| copied N failed M | フォルダ救出の成功 / 失敗件数 |
| copy failed: ... | 救出自体が始まらなかった |
| image 済み / 全体 | イメージの進捗 |
| image { ... } | イメージ完了。bad_lbas が不良セクタ数 |
| carved N | カービングで切り出したファイル数 |
| lost: N | 消失走査のヒット数（区画一覧の下にも出る） |
| select a disk first | ディスク未選択で GPT修復を押した |
| この区画は BitLocker です。... | その区画は暗号化されている。生読みではフォルダを出せない |
| GPT repaired ... | GPT修復が書いた |
| GPT repair failed: ... | 修復拒否または書き込み失敗 |
| error: ... | その他の失敗 |

## よくある見間違い

- Recovery のツリーを「C: が戻った」と思う。容量が数 GB なら Recovery。
- フォルダ救出の Windows 画面で、壊れたディスク上のフォルダを選んでしまう。あれは保存先。
- 消失走査の `lost: N` を「N 個のフォルダが戻る」と思う。シグネチャのヒット数。
- GPT修復でファイルが直ると期待する。直るのはヘッダと区画表だけ。
- SMART 正常ならファイルは全部読める、と思う。ファイルシステムの壊れと SMART は別。
- 今動いている C: でフォルダ救出を試し、空だからアプリが壊れていると思う。BitLocker なら仕様。
- イメージ保存先にソースと同じディスクを選ぶ。この版は拒まない。自分で別ドライブを選ぶ。

## やってはいけないこと

- 壊れたディスクを、ディスクの管理やインストーラでフォーマットする、初期化する
- 救出先に、壊れたディスク自身を指定する
- SMART 注意のディスクに、先に消失走査や GPT修復を繰り返す
- Recovery 区画のツリーを「C: が戻った」とみなす
- 両方死んでいる GPT に修復を期待する
- 鍵のない BitLocker を、カービングで復号できると思う
- TRIM 済み SSD の空き領域から消えたファイルを期待する。TRIM 後は空

## コマンドライン

`QuickDiskRescue_cli.exe` は UAC を出さない。JSON を標準出力する。管理者でないと物理ディスクは開けないことが多い。

- `list`
- `diagnose --source \\.\PhysicalDrive1`
- `diagnose --source disk.img --deep`
- `tree --source disk.img --partition 2`
- `copy --source disk.img --from /Users --out E:\rescued --partition 2`
- `image --source \\.\PhysicalDrive1 --out E:\disk.img`
- `carve --source disk.img --out E:\carved`
- `repair-gpt --source disk.img`
- `repair-gpt --source disk.img --write`
- `unlock --source \\.\PhysicalDrive1 --partition 2 --recoverypassword 123456-...`

`repair-gpt` は `--write` を付けない限り書かない（確認用）。GUI の GPT修復は確認のあと実際に書く。

`--partition` は区画一覧の `#N`。省略時はエンジン側の既定。GUI はクリックした行を使う。

## このアプリがすること / しないこと

すること:

- 物理ディスクまたはディスクイメージを、Windows のドライブレターなしで読む
- GPT / MBR、区画、SMART を診断する
- NTFS の $MFT が読めるとき、フォルダツリーを出して別ドライブへコピーする
- ディスク全体の生イメージを取る
- ファイル名が死んでいる領域から JPEG / PNG / GIF / PDF / ZIP を切り出す（カービング）
- 壊れた GPT ヘッダを、実容量に合わせて書き直す（GPT修復）

しないこと:

- フォーマット、初期化、区画の新規作成、ドライブレターの割り当て
- BitLocker の復号（鍵なしの生読みでは中身は出ない）
- SMART の自己診断テスト（短時間・長時間）
- 消失走査の候補オフセットから、自動でフォルダ救出を始めること
- 同じディスクへの保存の強制拒否（自分で避ける）
- FAT / exFAT / ReFS のフォルダ救出（この版は NTFS のみ）
