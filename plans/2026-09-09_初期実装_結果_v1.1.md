# 計画書: QuickDiskRescue 初期実装 結果 (v1.1)

承認された計画: `plans/2026-09-09_初期実装_v1.1.md`

## 実施内容

- `document/spec.md` / `spec_jp.md` を先に書いた。
- C++17 + WebView2 の GUI / CLI をビルドした。
- エンジン: 読取専用 raw I/O、STORAGE/DISK IOCTL 識別、GPT primary/backup、消失シグネチャ走査、NTFS $MFT ツリーとフォルダ copy-out、イメージ、JPEG/PNG/PDF/ZIP/GIF カービング。
- `QUICKAPPSTEST=1` では PhysicalDrive を開かない。GUI は `requireAdministrator`、CLI は asInvoker。
- ATA パススルーは書き込み権限ハンドルが必要なため未使用。識別は `IOCTL_STORAGE_QUERY_PROPERTY` と geometry。読み取りは `FILE_FLAG_NO_BUFFERING`。

成果物:
- `dist/binary/QuickDiskRescue.exe` (1762792 bytes)
- `dist/binary/QuickDiskRescue_cli.exe` (1026796 bytes)

## 検証結果

| 項目 | 結果 |
|---|---|
| ビルド | 成功 |
| 合成 GPT 不一致（1TB 相当の LastUsable vs 実 2MB） | `size_mismatch: true`、NTFS シグネチャ検出 |
| カービング | JPEG を 1 件救出（PASS、count>=1） |
| ソース GENERIC_READ のみ | `Source::open` は GENERIC_READ。WriteFile は出力側のみ |
| 実機の壊れた D: | 合格条件にしていない（別 PC 復旧中） |
| GUI 実画面 | 未起動（UAC）。検査モードでの目視は未実施 |
| 実 NTFS $MFT フォルダ copy-out | 合成イメージに MFT が無いため未検証 |

失敗の捏造なし。NTFS フォルダ救出はコードはあるが、完全な NTFS フィクスチャではまだ通していない。

## 残課題

- 実 NTFS ボリューム（または VHD）でのフォルダ copy-out の検証
- GPT 書き戻しは計画どおり未実装
- カービングの PDF 検出が JPEG のスキップ幅で漏れることがある
- About 用アイコン PNG は jpg 原本（`assets/QuickDiskRescue-icon.jpg`）
