# 計画書: QuickDiskRescue 初期実装(v1.1)

v1.0 からの差分: EaseUS 互換は不要。**フォルダ単位でできるだけ救出する。** Windows のマウントに頼らず、物理ディスクへ届く読み取り経路は全部使う。v1.0 は残す。本ファイルが新しい正。

## 目的

未マウント・容量表示異常・RAW のディスクから、元のフォルダ構造を保ったまま別ドライブへ救出する。ドライブ文字や NTFS ドライバを通さず、セクタ単位の生読みと識別コマンドでスキャンする。

## フォルダ単位救出の原則

パスが復元できる層を優先する。カービングはパスが無いファイルの最後の手段。

| 優先 | 情報源 | フォルダ構造 |
|---|---|---|
| 1 | $MFT の parent 参照 | 元のツリー |
| 2 | $MFTMirr（先頭 4 レコードの鏡） | ブートと $MFT 位置の復旧に使う |
| 3 | ディレクトリの $I30 INDX | MFT が欠けてもフォルダ名と子が出ることがある |
| 4 | ディスク上の別 NTFS ブート（消失パーティション） | そのボリューム内で 1〜3 を再実行 |
| 5 | シグネチャ・カービング | 原則パス無し。`RECOVERED/by_type/...`。隣接クラスタと残存ファイル名があれば推定フォルダに入れる |

UI の主操作は **フォルダを選んでサブツリーごとコピー**。ファイル単体選択も可。読めないクラスタは飛ばして、そのファイルを「部分救出」と印する。空フォルダも MFT に残っていれば作る。

## ハードウェアレベル走査（ソースへは一切書かない）

Windows から物理層へ届く **読み取り** は全部実装する。WRITE / TRIM / DST 長時間テストは実装しない（死にかけディスクを殺す）。

### A. 識別（スキャン前）

- `CreateFile(\\.\PhysicalDriveN)` `GENERIC_READ`
- `IOCTL_STORAGE_QUERY_PROPERTY`（Adapter / Device / AccessAlignment / SeekPenalty / Trim / Protocol）
- `IOCTL_DISK_GET_DRIVE_GEOMETRY_EX` / `IOCTL_DISK_GET_LENGTH_INFO`（論理容量。1TB vs 2TB の比較用）
- `IOCTL_STORAGE_GET_DEVICE_NUMBER`
- ATA: `IOCTL_ATA_PASS_THROUGH` で IDENTIFY DEVICE（USB ブリッジは失敗しうる → 失敗を表示して次へ）
- NVMe: `IOCTL_STORAGE_PROTOCOL_COMMAND` / ProtocolSpecific Identify / SMART log（対応コントローラのみ）
- SCSI: `IOCTL_SCSI_PASS_THROUGH_DIRECT` INQUIRY / READ CAPACITY(16)
- SMART: `IOCTL_STORAGE_PREDICT_FAILURE` と ATA SMART READ DATA。**表示のみ**。セルフテストは走らせない
- 512e / 4Kn / 論理セクタと物理セクタの不一致を診断に出す

### B. 生読み（OS キャッシュを使わない）

QuickDiskBench と同じ系統:

- `FILE_FLAG_NO_BUFFERING | FILE_FLAG_OVERLAPPED`
- セクタ整列バッファ、4MiB 順次、キュー深さ制限付き並列（死にかけディスクでは 1 に落とす）
- ReadFile が失敗した LBA は、ATA/SCSI/NVMe の READ コマンドへフォールバック（パススルーが使えるときだけ）
- リトライ回数・タイムアウトを設定可能。尽きたらその LBA を不良として記録し続行
- 再開用に最終成功 LBA をチェックポイント

### C. 構造スキャン（マウント不要）

全ディスク（または指定レンジ）をセクタ単位で探し、見つかった候補を一覧にする。

- Protective MBR / 通常 MBR
- GPT header マジック `EFI PART`（先頭と末尾、および途中に残ったコピー）
- NTFS ブート `NTFS    `（パーティション先頭以外も）
- NTFS バックアップブート（BPB が示す末尾）
- MFT レコードマジック `FILE`（$MFT が迷子のとき）
- FAT32 / exFAT ブート（見つかれば読む。v1 のツリー救出は NTFS 優先、FAT はシグネチャ救出の補助）

「Lost Partition」はこれで出す。容量の食い違いは GPT LastUsableLBA vs `GET_LENGTH_INFO` vs IDENTIFY の 3 点比較。

### D. NTFS メタデータ（フォルダ救出の本体）

未マウント、パーティションオフセット付き raw:

- $Boot / backup boot
- $MFT データランを追う
- $MFTMirr
- 各 FILE レコード: 名前、親、ディレクトリフラグ、データラン、有効サイズ
- ディレクトリ $I30
- 削除フラグが立っているレコードも「削除済み」としてツリーに出す（上書きされていなければコピー可）
- $Bitmap が読めたら、カービングは未割り当てクラスタだけに限定して時間を減らす

### E. カービング（パスが死んだ領域）

メタデータが無いクラスタを、ヘッダ／フッタで切る。v1 で載せる型（拡張可能な表）:

- 画像: JPEG, PNG, GIF, BMP, TIFF, WEBP
- 文書: PDF, OLE (doc/xls/ppt), OOXML (zip 容器), ZIP, 7z, RAR
- メディア: MP4/MOV (ftyp), MP3, WAV
- その他: SQLite, EXE/DLL, PST はサイズが大きいので任意

フォルダに戻せないファイルは `RECOVERED/carved/<type>/`。MFT 上の既存ファイルとクラスタが重なるものはカービングしない（二重救出を避ける）。

### F. イメージ

ソース read-only のディスクイメージ。不良 LBA はゼロ埋め + マップファイル。以降の重い走査はイメージを優先（実ディスクへの負荷を止める）。UI は「先にイメージを推奨」と出すが、直接スキャンも選べる。

## 検証方法

1. 合成 NTFS: `a/b/c/file.txt` をフォルダ `a` 指定で copy-out し、先側に同じ相対パスができる。
2. ブート破損フィクスチャ: backup boot から $MFT に届き、フォルダ救出できる。
3. GPT 不一致フィクスチャ: 3 種容量と primary/backup の差が JSON に出る。
4. カービングフィクスチャ: 未割り当て JPEG が `RECOVERED/carved/jpeg/` に出る。MFT 上ファイルと二重に出ない。
5. ソースハンドルに WriteFile / SCSI WRITE が無い（テストまたはコード検索）。
6. `QUICKAPPSTEST=1` で PhysicalDrive を開かない。
7. 保存先がソースならエラー。
8. GUI: フォルダ選択コピー、日英、バージョン情報、読取専用表示。
9. 実機 D: は合格条件にしない。

## リスク

- 1TB の全セクタ走査は数時間。進捗・再開が無いと実用にならない。
- 死にかけディスクへの並列読みは状態を悪化させる。既定キューは 1。SMART 警告時はさらに間を空ける。
- USB-SATA は ATA パススルーが死ぬことが多い。ReadFile だけで完走できること。
- SSD の TRIM 済み領域はハードウェア走査しても空。できないことは UI に書く。
- カービングは誤検出する。フォルダ救出の結果と混ぜて「完全復元」と表示しない。
- $I30 と MFT が食い違うとツリーが壊れる。MFT を正、INDX は補完、衝突は警告。
