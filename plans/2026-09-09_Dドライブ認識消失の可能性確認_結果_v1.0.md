# 2026-09-09 Dドライブ認識消失の可能性確認 結果 v1.0

## 質問

ページファイルが壊れて、Windows から D ドライブが認識されなくなった可能性はあるか。

経緯:
- AI×2 コーディング中にメモリエラーで Windows が落ちた
- ページファイル配置先の D が認識されなくなった
- 再起動後にディスク復旧が走り完了
- パーティションは見えるがサイズが 1TB→2TB
- マウントされず D: が出てこない
- 現在復旧中

## 結論

**pagefile.sys 単体が壊れたからドライブごと消えた、という公式の因果はない。**
ページファイル破損の公式な落ち先は「一時ページング ファイルを作った」警告であり、ボリューム非マウントや容量改変ではない。

**ただし「D をページファイルで埋めながらクラッシュしたことが、NTFS / パーティション情報の破損を誘発した」可能性はある。** その場合、壊れたのは pagefile.sys ではなく、ファイルシステムまたはパーティションテーブル側。

**1TB が 2TB と出る点は pagefile 破損では説明できない。** これはディスク識別・GPT/MBR・パーティション終端 LBA の層。

## 根拠

### ページファイルが壊れたときの公式・既知症状

- 「Windows created a temporary paging file on your computer because of a problem that occurred with your paging file configuration」
- 起動時に C: へ一時 pagefile を作って継続する
- ドライブ全体を隠す・容量を倍にする、という記述は見つからない

### ディスク満杯と非マウントの公式

Microsoft: ボリュームが RAW に見える原因の一つが
「There is not enough disk space for the file system extend」
（ファイルシステム拡張に空きが足りない）
https://learn.microsoft.com/en-us/previous-versions/troubleshoot/windows-server/volume-show-up-as-raw

ページファイルが D を埋め尽くすと、NTFS のトランザクションログ拡張に失敗し、マウントできない状態になり得る。これは「pagefile が壊れた」ではなく「空きゼロで NTFS が破綻した」。

### 突然の電源断 / クラッシュ

- dirty bit が立つ → 次回起動で autochk / chkdsk（「ディスクの復旧」に相当しうる）
- NTFS Event ID 55: ファイルシステム構造が壊れて使用不能
- ボリューム状態 Unknown: ブートセクタ破損でデータにアクセスできない
  https://learn.microsoft.com/en-us/troubleshoot/windows-server/backup-and-storage/troubleshoot-disk-management

### 1TB→2TB

- MBR の上限は約 2.2TB。GPT の primary / backup ヘッダ不一致でサイズが食い違う事例はある
- バックアップ GPT はディスク末尾。パーティションが末尾まで食い込み、ファイルで埋めるとバックアップ GPT を壊しうる（GPT の構造上の既知リスク）
- これは pagefile.sys の中身が壊れた、という意味ではない

## 時系列として整合する説明

1. コミット枯渇 → メモリエラー → クラッシュ（前回調査どおり）
2. その直前、D 上の pagefile が急拡大し空きが尽きた可能性
3. 空きゼロ + 不完全な書き込みで NTFS dirty / Event 55 / RAW
4. 再起動で autochk
5. パーティション情報または GPT が壊れ、サイズ表示が狂い、レター未割り当てでエクスプローラーに出ない

## やってはいけないこと（復旧中）

- ディスクの初期化
- フォーマット
- パーティションの新規作成
- データ未退避での chkdsk /r（不良セクタ疑いなら負荷で悪化しうる）
